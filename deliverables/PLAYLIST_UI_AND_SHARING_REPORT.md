# Playlist UI, ⋮ menu, sharing & content experience — report

Branch/working copy only. **Nothing was pushed, merged or deployed; no Production SQL, env vars, webhooks or bot settings were touched.**
Full design notes: `docs/PLAYLIST_SHARING_AND_VIEWER.md`.

## 1. New playlist experience
* "Playlist" label removed; title is the `<h1>`. Header: derived cover, title, description, file count, total size, Public/Private + Password/Stars chips.
* Actions: **Play first**, **Share** (prominent), **⋮** (Edit, Share, Copy link, Delete). Bottom *Delete playlist* and the visible *Edit* button removed;
  delete still uses `DeleteConfirmModal` + the existing `DELETE /api/playlists/:id`.
* YouTube-style rows: position, 16:9 thumbnail, 2-line title, type · size, status chips; tap opens the file; swipe-remove, drag reorder, add/move preserved.

## 2. Sharing & public access
* New additive column `playlists.share_slug` (random 96-bit token). Public page `/p/<token>`, API `GET/POST /api/p/<token>`, owner endpoint `POST /api/playlists/:id/share`.
* Private → cannot be shared until made public (dialog offers it); password → recipients must enter it (HttpOnly HMAC cookie, rate-limited); Stars price → locked/refused (no payment backend exists).
* Public payload lists only **published** files and exposes no ids, hashes, Telegram links/ids or channels. Each item opens the existing `/f/<slug>` page, which still enforces the file's own password/price.
* Share dialog: Copy link, Share on Telegram (`openTelegramLink` in the Mini App, new tab elsewhere), native share where supported, toasts for success/failure.
* Public page sets Telegram `ready()/expand()` and wires the native Back button; link-preview metadata has only title/description.

## 3. Sequential viewing
Existing file page + `?list=<token>&i=<n>` → `PlaylistNavBar`: "3 of 12", Previous, Next, Back to playlist, in saved order; position resolved by slug server-data, never by the query value.
No fake player (files are delivered via Telegram), no autoplay. "Continue" on the public page (device-local). Shuffle intentionally omitted.

## 8. Known limitations
* No in-app media playback: Onfile delivers originals via Telegram, so "next" opens the next file's page; nothing auto-plays. No duration anywhere (no metadata).
* Shuffle not implemented. "Continue" is per-device.
* Stars playlists cannot be shared and remain locked until a real Stars payment/entitlement backend exists.
* A file that is also published on its own has its own public link; the playlist password protects the playlist view, not that file's independent link (file rules apply).
* The mobile "no horizontal overflow" and light/dark checks are DOM/class-level assertions (jsdom has no layout engine; no browser was available in the sandbox) — please do a real-device pass.
* Pre-existing ESLint errors in unrelated files (`react-hooks/set-state-in-effect`) were left untouched.
